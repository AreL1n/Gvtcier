# Sandbox —— 引擎调试沙箱

把引擎当子进程启动，捕获它的全部输出与崩溃信息，落盘成文件。

解决的核心问题：引擎一崩，控制台信息随窗口一起消失，拿不到任何可用线索。

## 编译

```
cd src/sandbox
python build.py
```

产物 `src/sandbox/dist/Sandbox.exe`，无第三方依赖，只用到系统 API。

## 用法

### 方式一：双击进终端（交互模式）

直接双击 `Sandbox.exe`，进入一个命令提示符，在里敲命令：

```
Gvtcier 沙箱  输入 help 查看命令, exit 退出
----------------------------------------

D:\Code\Work\Gvtcier\Sandbox
> run ..\dist\Gvtcier.exe

（程序输出实时滚动）

D:\Code\Work\Gvtcier\dist  [上次: 正常结束]
> crash
---------- crash_20260925_113811.log ----------
...
```

交互命令：

| 命令 | 说明 |
|------|------|
| `run <exe> [参数...]` | 运行程序，输出实时滚动 |
| `cd <目录>` | 切换工作目录 |
| `ls` | 列出当前目录 |
| `pwd` | 显示当前目录 |
| `crash` | 显示最近的崩溃报告 |
| `logs` | 用资源管理器打开日志目录 |
| `help` | 显示帮助 |
| `exit` / `quit` | 退出 |

提示符会显示上次运行结果和日志位置，`crash` 自动去那里找。

### 方式二：命令行一次性运行

```
Sandbox.exe -run <可执行文件> [参数...]
```

适合脚本调用、CI：

```
Sandbox.exe -run dist\Gvtcier.exe
Sandbox.exe -run dist\Gvtcier.exe game.lua
Sandbox.exe -run dist\Gvtcier.exe --server 22800 room1
```

### 选项

| 选项 | 说明 |
|------|------|
| `-run <exe>` | 目标程序，相对或绝对路径，必填 |
| `-timeout <秒>` | 超过时长强制终止，缺省不限。用于挂机测试防卡死 |
| `-dir <目录>` | 子进程工作目录，缺省为 exe 所在目录 |
| `-quiet` | 不回显到终端，只写日志。适合批量跑 |
| `-h` | 显示帮助 |

`-run` 之后除选项外的参数原样传给子进程。

## 产物

日志写在**目标程序同目录**的 `logs/` 下：

| 文件 | 内容 |
|------|------|
| `logs/session_<时间戳>.log` | 完整会话输出，含程序、工作目录、开始时间、全部 stdout/stderr |
| `logs/crash_<时间戳>.log` | 崩溃报告，仅异常终止时生成 |

时间戳格式 `20260925_112626`，每次运行独立文件，不会互相覆盖。

## 崩溃报告内容

异常终止时，`crash_*.log` 含：

```
=== Gvtcier 崩溃报告 ===
程序: "D:\...\dist\Gvtcier.exe"
工作目录: D:\...\dist
完整日志: D:\...\dist\logs\session_20260925_112626.log

========================================
  引擎异常终止
========================================
退出码: 0xC0000005
原因: 访问违例 (空指针或越界读写) [0xC0000005]
运行时长: 5.1 秒
捕获输出: 884 字节

最后输出片段:
----------------------------------------
（崩溃前最后 4KB 的输出）
========================================
```

## 退出码对照

沙箱把 Windows 异常码翻译成人话：

| 退出码 | 含义 |
|--------|------|
| `0` | 正常退出 |
| `0x3` | CRT abort（未捕获 C++ 异常、断言失败、主动中止） |
| `0xC0000005` | 访问违例（空指针、越界读写）—— 最常见 |
| `0xC0000094` | 整数除零 |
| `0xC00000FD` | 栈溢出（递归过深、局部变量过大） |
| `0xC0000374` | 堆损坏（重复释放、越界写堆） |
| `0xC0000409` | 栈缓冲区溢出 / 安全 Cookie 校验失败 |
| `0xC0000017` | 内存耗尽 |
| `0xC0000135` | 找不到依赖 DLL |
| `0xC0000142` | DLL 初始化失败 |
| `0x40000015` | CRT abort（另一种表现） |
| `0x0000DEAD` | 被沙箱超时终止 |

对照表能直接告诉你是哪类问题：`0xC0000005` 查指针，`0xC0000374` 查内存管理，`0xC00000FD` 查递归。

## 典型场景

### 引擎启动就闪退

```
Sandbox.exe -run dist\Gvtcier.exe
```

看 `logs/crash_*.log` 的「最后输出片段」，能知道崩在哪一步（窗口创建？着色器编译？脚本加载？）。

### 挂机测试防卡死

```
Sandbox.exe -run dist\Gvtcier.exe -timeout 300
```

跑 5 分钟自动收工。如果卡在死循环，超时会被捕获并报告，最后输出能看出卡在哪。

### 批量跑脚本收集日志

```
Sandbox.exe -run dist\Gvtcier.exe test1.lua -quiet
Sandbox.exe -run dist\Gvtcier.exe test2.lua -quiet
```

`-quiet` 不回显，全靠日志文件。

### 只想要某个脚本的报错

Lua 报错也会进 `session_*.log`：

```
[GvtcierLua] [string "..."]:9: 尝试索引空值nil (local '甲')
```

## 注意

- 沙箱不改变被托管程序的行为，只做进程包装与输出捕获
- 子进程输出是**实时**转发的，不是等结束才显示
- 程序如果自己创建了新窗口，窗口不受沙箱影响
- 沙箱不注入任何代码到子进程，所以不需要引擎侧配合
- 单个会话最多缓存 16MB 输出用于崩溃报告，超出部分只写文件不进报告
